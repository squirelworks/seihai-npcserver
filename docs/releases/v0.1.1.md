A small release of **seihai-npcserver**: four GS1 features that did nothing in v0.1.0 now work.

## What changed

- **`playerleaves` runs.** The NPC-server already fired it when a player left a level, but seihai-core v0.0.5 did not know the event, so `if (playerleaves)` blocks never ran. This release is built on seihai-core v0.0.6, which lists it as a 2.1-era event.
- **`playerswordpower` and `playershieldpower`** are sent to the gserver as player props 8 and 9. The gserver keeps the sword or shield image it last sent for that player.
- **`playerhp`** is sent as player prop 2, the same half-hearts value as `playerhearts`.

## Tested with

- Loopback tests against the stand-in gserver, including a new `playerleaves` test that fails on seihai-core v0.0.5.

## Not in this release

- seihai-gserver does not yet act on what the NPC-server sends (seihai-gserver#53). Until it does, the stand-in gserver (`cargo run --example mock_gserver`) is the way to see the results.
- `sendtoserver` and the selected weapon are still logged and skipped.

## Download and run

Pick the archive for your system: Linux x86_64, Windows x86_64, macOS Intel (x86_64) or macOS Apple Silicon (aarch64). Most setups let seihai-gserver start it (`npcserver = auto`). To run it yourself:

```
seihai-npcserver --gserver 127.0.0.1:14810 --token-file npcserver-token.txt --world path/to/world
```

On macOS, the first start may need right-click → Open, because the build is not signed.
